# Импорт из Excel, экспорт и печать

## Импорт: format-agnostic по решению, а не по случайности

Присланные xlsx были **образцами предметной области**, не спецификацией формата
(решения п. 5, 17, 47); в репозитории они не лежат. Реальные данные вводятся руками
или приходят другим файлом. Поэтому
парсер под конкретный файл писать нельзя: путь пользователя — любой xlsx → выбор листа →
мастер сопоставления колонок → предпросмотр → сохранённый профиль.

### Слои

| Слой | Файл | Что знает |
|---|---|---|
| Чтение книги | `main/import/workbook.ts` | `exceljs`; разворачивает формулы (берёт кэш результата), richText, даты → `YYYY-MM-DD` |
| Движок разбора | `shared/import/engine.ts` | чистые функции над `Grid = Cell[][]`; ни Excel, ни БД |
| Применение | `main/import/apply.ts` | колонки уже сопоставлены с полями; ищет существующие справочные записи и создаёт строки |
| Мастер | `renderer/src/features/import/ImportWizardPage.tsx` | шаги UI, формат `mappingJson` профиля |

### Механизмы движка (включаются настройкой, не зашиты под образцы)

- `applyContextInheritance(rows, columns)` — «пустая ячейка = значение строкой выше» для
  выбранных колонок, уровни иерархии слева направо: новое значение во внешней колонке
  сбрасывает вложенные (иначе первая строка нового блока унаследует преподавателя предыдущего);
- `filterServiceRows(rows, pattern)` — «Итого/ВСЕГО» это контрольные суммы, а не данные;
  правило — регулярное выражение или список слов через `|`;
- `reconcileTotals(...)` — сверка данных с отфильтрованными контрольными строками;
- `collectDiscrepancies` / `resolveDiscrepancies` — разная численность одной группы в файле
  считается ошибкой: варианты («17 в 6 строках, 30 в 9») показываются и разрешаются
  пользователем, молча не берётся ни один (решения п. 43);
- `applyBlockHeaders(rows, rules)` — строки-заголовки блоков: «число в B → дисциплина из D»,
  «текст в B → преподаватель из B». Заголовок не становится записью, его значение получают
  строки блока ниже; срабатывает первое подходящее условие, порядок правил — уровни иерархии.
  Нужен, когда значение лежит в той же колонке, что у строк данных другое поле (годовая
  нагрузка: дисциплина в колонке группы), — там «наследование» бессильно;
- `mapToEntity(rows, columns, contexts?)` + `TARGET_SCHEMAS` — целевые сущности `curriculum`,
  `teaching_load`, `teacher`, `calendar_period` и их поля. Если одно поле сопоставлено
  нескольким колонкам, таблица «широкая»: каждая колонка даёт из строки отдельную запись, а
  недостающие признаки (вид занятия, полугодие) берутся из `constants` колонки — мастер
  подставляет их из шапки (`columnHeaderHints` + `guessColumnConstants`). Пустая ячейка и ноль
  в такой колонке — записи нет;
- у нагрузки есть необязательное поле `halfYear`: запись уходит в семестр этого полугодия того
  же учебного года, поэтому годовая нагрузка загружается одним проходом;
- разбор значений: `cellNumber` (русские разряды с обычным, неразрывным U+00A0 и узким
  U+202F пробелом, запятая как разделитель), `parseIsoDate`, `parseEnum` + словари синонимов
  `LESSON_KIND_SYNONYMS`, `CALENDAR_KIND_SYNONYMS`, `TEACHER_CATEGORY_SYNONYMS`,
  `matchesPersonName`.

Расширяя разбор, добавляй синоним в словарь и тест в `tests/import/engine.test.ts` — не
специальную ветку под конкретный файл.

Сквозной регресс «xlsx → мастер → БД» — `tests/db/import-annual-load.test.ts`: синтетическая
книга той же формы, что годовая нагрузка, проверяется всегда; настоящий файл колледжа в
репозиторий не кладётся и подхватывается из `IMPORT_ANNUAL_LOAD_XLSX` (или из корня проекта),
без него эти тесты пропускаются. Тест идёт путём онбординга: пустой учебный год → поставляемый
профиль → «Завести недостающее» → применение; цепочка мастера для тестов —
`tests/db/annual-load-fixtures.ts::buildRecords`.

### Применение

`apply.ts` **не изобретает отсутствующие справочные записи молча**: если дисциплина, группа
или преподаватель не найдены, строка уходит в `skipped` с человеческой причиной. Есть ключ
«уже есть» — повторная заливка того же файла (обычный сценарий: завуч поправил пару строк)
не плодит дубли, повторы попадают в пропущенные. Импорт целиком идёт как
`runOperation('import', …)`, поэтому откатывается целиком.

Но завуч может завести недостающее **явно**: для нагрузки шаг 5 мастера спрашивает main
(`import:preflight` → `main/import/missing.ts`), чего не хватает — специальностей (по каталогу
решения п. 45), дисциплин, преподавателей («Янхаева З.» → фамилия и инициал), групп (разбор
«КСД-21», п. 41; численность из файла), учебных планов и их строк (часы по видам — максимум по
группам плана, кредиты = часы ÷ 30, план черновиком), квалификаций. Кнопка «Завести
недостающее» (`import:createMissing`) создаёт всё это отдельной операцией `import` после
подтверждения; план пересчитывается в main внутри транзакции, отчёту из renderer не доверяем.
Что завести нельзя (имя группы не разобрать, численность группы в файле расходится — п. 43,
семестр за сроком обучения), уходит в `problems` с объяснением. Откат: операция «заведено из
файла» не откатывается, пока жив импорт, который на неё ссылается (`OperationDependedError`).

Профиль (`import_profile`) хранит только *как читать*: диапазон, сопоставление колонок,
наследование, правило служебных строк, строки-заголовки и колонки проверки расхождений. Ни
пути к файлу, ни имени листа — намеренно. Формат — `SavedMapping` в `shared/import/presets.ts`;
там же готовые профили (`IMPORT_PRESETS`), которые мастер показывает как «Готовый: …», а экран
«С чего начать» открывает ссылкой `#/import?preset=annual-load`. Готовый профиль — не парсер под
файл (п. 47): то же сопоставление, которое завуч собрал бы сам; его раскладка проверяется на
настоящем файле в регрессе выше.

## Онбординг: «С чего начать»

`features/onboarding/OnboardingPage.tsx`, канал `onboarding:status` (`db/repo/onboarding.ts`).
Дистрибутив ставится с пустой базой, поэтому стартовая страница (`StartRedirect`) ведёт на
чек-лист шагов в порядке зависимостей, пока не пройдены обязательные; статус каждого шага
(`done` / `todo` / `review`) и конкретная причина считаются в main по данным, renderer держит
только тексты. Новый обязательный справочник — новый шаг там же.

## Экспорт

- `main/export/excel.ts` — расписание группы, преподавателя и сводное (лист на группу), плюс
  отчёты этапа 7. Строится на `templateEntriesView` — **том же представлении**, что видит
  экран шаблона недели, чтобы печать и экран не расходились.
- `main/export/pdf.ts` — HTML + вёрстка под печать → `webContents.printToPDF` в скрытом окне
  (`printHtmlToPdf`). Расписание — A4 альбомная, табличные отчёты — A4 книжная. Отдельного
  движка вёрстки нет; HTML собирается строками, всё пользовательское проходит `escapeHtml`.

Утверждённых бланков не существует (решения п. 28) — верстать по своему усмотрению, замечания
завуча ожидаемы.
